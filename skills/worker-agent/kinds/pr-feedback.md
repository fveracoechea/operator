# PR feedback

Load `no-slop` before writing replies.
Load `resolving-merge-conflicts` when resolving a merge conflict.
Read the PR's comments, reviews, checks, and unresolved threads.
Check each claim before changing code.
Treat the reviewer's note as open points to check, not as evidence.
Reply directly, one short reply per piece of feedback.
Run the affected checks and push fixes to this PR.
Follow the router's PR feedback workflow with `operator pr wait --json` and its guarded merge.
