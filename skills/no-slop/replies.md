# Replies to the person

Replies to the person you work for, in a terminal or an agent pane.
The reader knows the task and wants the result.

## Tone and length

- Write direct and relaxed, like a teammate who reports back.
- Give the answer or the outcome first. Put the evidence after it.
- Keep the reply as short as the result allows. Skip a recap of the request.

## Content

- Mark each claim as verified or not verified, and name the command or file that proves it.
- Give a code location as `file_path:line_number`.
- Name each step you skipped and each check that failed, with its output.
- Put a decision that the person must make at the end, as one clear question.

## Format

- Use bullets for two or more findings, and a numbered list for steps the person must do.
- Bold the decision or the blocker, so it stands out in a long reply.
